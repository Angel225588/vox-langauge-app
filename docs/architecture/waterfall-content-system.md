# Waterfall Content System — Architecture

> The single-source-of-truth document for how content flows from onboarding through the entire Vox learning experience.

## Overview

Vox uses a **waterfall content system** where vocabulary and learning content cascade through three phases, expanding progressively. Both the guided Staircase and the free-form Practice Tab share the same intelligence layer (Feedback Library), ensuring coherent, personalized learning across all modes.

```
┌─────────────────────────────────────────────────────────────────────┐
│                    WATERFALL CONTENT SYSTEM                         │
│                                                                     │
│  PHASE 1: ONBOARDING (unauthenticated)                             │
│  ├── 80-100 core words → Word Bank (everyone gets these)            │
│  ├── Discovery lesson prepared (first stair unlocked)               │
│  └── Practice Tab LOCKED (requires sign-up)                         │
│                                                                     │
│  PHASE 2: SIGN-UP EXPANSION (authenticated)                        │
│  ├── Expanded vocabulary: phrasal verbs, idioms, objects            │
│  ├── Staircase content: lectures, writing, listening, dialogues     │
│  ├── Practice Tab UNLOCKED: free playground, same user focus        │
│  └── Call scenarios prepared for Practice Tab                       │
│                                                                     │
│  PHASE 3: CONTINUOUS LOOP                                           │
│  ├── Lessons/Practice → Feedback → Library updated                  │
│  ├── Both agents read from same Feedback Library                    │
│  └── Next content adapts based on performance                       │
└─────────────────────────────────────────────────────────────────────┘
```

---

## Phase 1: Onboarding (Unauthenticated)

### What Happens
1. User completes V3 onboarding (language, level, profession, scenarios)
2. `creating-path.tsx` runs a 4-step live progress checklist:
   - **Step 1**: `generateInitialVocabulary()` → 85 core words via Gemini
   - **Step 2**: `generatePreviewStairs()` → skeleton staircase (template-based, $0)
   - **Step 3**: Library setup (placeholder)
   - **Step 4**: Path personalization (Supabase or preview)
3. User lands on home screen with staircase displayed
4. First stair is unlocked (Discovery Lesson)

### Initial Vocabulary (80-100 Words)
- Generated by `lib/word-bank/initialVocabGenerator.ts`
- **Every user gets these** regardless of auth status
- Level-adaptive: A1-only for beginners, B1-C1 mix for advanced
- Categories: greetings, questions, verbs, polite phrases, emergency, time, connectors, daily essentials, idioms
- Stored in Word Bank via `addOrReinforceWord()`
- Tagged with `milestoneTags: ['onboarding']`

### Discovery Lesson
- First stair (order=1) with `status: 'current'`
- Activity sequence varies by level:
  - **Beginner**: Vocab → Listening → Voice (30s)
  - **Intermediate**: Listening → Reading → Voice (60s)
  - **Advanced**: Listening → Voice (90s) → Writing
- Content draws from the 80-100 onboarding words

### Practice Tab
- **LOCKED** until sign-up
- Visual indication that signing up unlocks free practice
- Prevents anonymous users from consuming AI tokens on practice mode

## Phase 2: Sign-Up Expansion (Authenticated)

### Trigger
User signs up / signs in → expansion flow fires

### What Gets Generated
1. **Expanded Vocabulary**
   - Phrasal verbs relevant to user's scenarios
   - Idioms and expressions for their profession
   - Objects and nouns for their daily contexts
   - Formal vs informal register variations
   - Based on: onboarding data + initial word bank

2. **Staircase Content** (AI Agent)
   - Reads onboarding data + word bank
   - Generates per-stair content:
     - **Lectures**: Reading passages with comprehension questions
     - **Writing tasks**: Prompts and guided exercises
     - **Listening dialogues**: AI-generated dialogues with TTS
     - **Speaking scenarios**: Voice conversation setups
   - Lazy generation: only generates for current + next stair

3. **Practice Tab Content** (AI Agent)
   - Same source: onboarding + word bank + feedback history
   - Generates:
     - Free-form conversation scenarios for calls
     - Writing prompts based on user's weak areas
     - Listening exercises targeting pronunciation gaps
     - Reading passages at appropriate CEFR level
   - **Self-paced playground**: no stair gating, user chooses activity

4. **Call Scenarios**
   - Prepared for the Practice Tab's voice section
   - Based on user's selected scenarios from onboarding
   - Progressive difficulty based on conversation history

## Phase 3: Continuous Loop

### Shared Feedback Library (Source of Truth)

```
┌──────────────────────────────────────────────────────┐
│              FEEDBACK LIBRARY                         │
│                                                      │
│  ┌─────────────┐     ┌──────────────────┐           │
│  │  Word Bank   │     │ Feedback History  │           │
│  │ (SQLite)     │     │ (Supabase)        │           │
│  │             │     │                  │           │
│  │ - words     │     │ - session scores  │           │
│  │ - mastery   │     │ - KPI trends      │           │
│  │ - FSRS state│     │ - error patterns  │           │
│  │ - sources   │     │ - vocab usage     │           │
│  │ - tags      │     │ - conversation    │           │
│  └──────┬──────┘     │   transcripts     │           │
│         │            └────────┬─────────┘           │
│         └─────────┬──────────┘                      │
│                   │                                  │
│         ┌─────────▼──────────┐                      │
│         │  Intelligence Layer │                      │
│         │  (Shared by both)   │                      │
│         └────┬──────────┬────┘                      │
│              │          │                            │
│    ┌─────────▼───┐  ┌──▼─────────────┐             │
│    │  Staircase   │  │  Practice Tab   │             │
│    │  Agent       │  │  Agent          │             │
│    │             │  │                │             │
│    │ Guided path │  │ Free playground │             │
│    │ Sequential  │  │ User chooses    │             │
│    │ Gated       │  │ No gating       │             │
│    └─────────────┘  └────────────────┘             │
└──────────────────────────────────────────────────────┘
```

### How Both Agents Use the Library

| Agent | Reads | Writes |
|-------|-------|--------|
| **Staircase Agent** | Word bank (vocab for lessons), feedback history (weak areas), conversation transcripts (past performance) | Lesson scores, new words encountered, stair completion status |
| **Practice Tab Agent** | Same word bank, same feedback history, same transcripts | Practice scores, new words from free practice, error patterns |

### The Vocabulary-to-Everything Loop

```
Word Bank (FSRS)
    ↓
Pre-activity vocab review (targeted words)
    ↓
Activity (reading/writing/listening/speaking)
    ↓
Post-activity analysis
    ├── Used words → reinforce in Word Bank (FSRS: Good)
    ├── Missed words → flag in Word Bank (FSRS: Again)
    ├── New words encountered → add to Word Bank
    └── Scores → Feedback History
    ↓
Next activity adapts based on updated state
```

## 3-Tier Practice Waterfall (Technical)

When any practice mode needs vocabulary, it uses this resolution order:

```typescript
// lib/ai/practiceGenerator.ts → getVocabAndProfile()

Tier 1: Staircase Content (authenticated + active path)
  → getStairContent(stepId) + getStaircaseParams(userId)
  → Extracts vocab, grammar, scenarios from current stair
  → Cost: Free (already loaded)

Tier 2: Word Bank (after onboarding)
  → getWordsByPriority(25) from SQLite
  → Populated by initialVocabGenerator
  → Cost: Free (local storage)

Tier 3: Onboarding Only (minimal fallback)
  → Profile data only (language, level, scenarios)
  → Triggers generic Gemini prompts
  → Cost: 1 API call
```

## Design Decisions

1. **Why 80-100 words at onboarding?** — Gives users enough vocabulary to meaningfully engage with the discovery lesson and first few practice sessions without requiring sign-up.

2. **Why lock Practice Tab until sign-up?** — Practice mode generates AI content per-session (costs tokens). Gating behind auth prevents anonymous token consumption and gives us the user context needed for personalization.

3. **Why share the same Feedback Library?** — A user practicing "writing" in the Practice Tab should improve their writing performance in the next Staircase lesson. Separate libraries would create a split-brain problem where the staircase agent doesn't know about practice improvements.

4. **Why lazy generation?** — Only generating content for the current + next stair keeps costs proportional to active users, not total users. Average cost per active user ≈ 2-3 Gemini calls per session.

5. **Why FSRS over SM-2?** — FSRS provides more accurate interval scheduling, especially for the vocabulary-to-conversation loop where words get reinforced through conversation (not just flashcard reviews).
