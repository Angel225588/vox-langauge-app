### 4. RLS Policy Missing on staircase_steps
**Error:** `new row violates row-level security policy for table "staircase_steps"`

**Root Cause:** Schema had RLS enabled but NO INSERT policy for `staircase_steps` table.

**Fix:** Added SQL policies to Supabase:
```sql
CREATE POLICY "Users can insert own staircase steps"
  ON staircase_steps FOR INSERT
  WITH CHECK (
    staircase_id IN (
      SELECT id FROM user_staircases WHERE user_id = auth.uid()
    )
  );

CREATE POLICY "Users can insert vocabulary for own stairs"
  ON stair_vocabulary FOR INSERT
  WITH CHECK (
    step_id IN (
      SELECT s.id FROM staircase_steps s
      JOIN user_staircases sc ON s.staircase_id = sc.id
      WHERE sc.user_id = auth.uid()
    )
  );
```

## Feature Request: Vox Library System

### Overview
AI-powered content curation system that:
1. Finds relevant online learning resources
2. Curates them into a "Vox Library" (master content pool)
3. AI selects personalized content for each user
4. Users can browse full Vox Library if desired

├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐  │
│  │   SOURCES    │    │  VOX LIBRARY │    │ USER LIBRARY │  │
│  │              │    │   (Master)   │    │ (Personal)   │  │
│  │ • Online     │───▶│              │───▶│              │  │

│  │ • APIs       │    │   Content    │    │   for user   │  │
│  │ • Datasets   │    │ • All levels │    │ • Matches    │  │
│  │              │    │ • All topics │    │   goals      │  │
│  └──────────────┘    └──────────────┘    └──────────────┘  │
│         │                   │                   │           │
│         │                   │                   │           │

### Database Schema (Proposed)

```sql
-- Master library of all curated content
CREATE TABLE vox_library (
  id UUID PRIMARY KEY,
  content_type TEXT NOT NULL, -- 'vocabulary', 'story', 'article', 'video', 'podcast'
  title TEXT NOT NULL,
  description TEXT,
  source_url TEXT,
  source_name TEXT,
  language TEXT NOT NULL,
  difficulty TEXT NOT NULL, -- CEFR level
  topics TEXT[] NOT NULL,
  content_data JSONB NOT NULL, -- Actual content
  ai_quality_score FLOAT, -- AI-assessed quality
  created_at TIMESTAMP DEFAULT NOW()
);

-- User's personalized library
CREATE TABLE user_library (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id),
  vox_item_id UUID REFERENCES vox_library(id),
  added_by TEXT NOT NULL, -- 'ai' or 'user'
  relevance_score FLOAT, -- AI-calculated relevance to user
  status TEXT DEFAULT 'active', -- 'active', 'completed', 'archived'
  added_at TIMESTAMP DEFAULT NOW()
);
```

## Bug: Word Bank Data Persistence

### Current Behavior
- User deletes account from Supabase
- User's Supabase data is deleted
- Word Bank still shows data in app
- This is unexpected/confusing behavior

### Root Cause
Word Bank is stored in **local SQLite database** (`lib/db/flashcards.ts`)
- Data is NOT tied to authenticated user
- No sync between SQLite and Supabase
- Logout/deletion doesn't clear local data

### Fix Options

**Option A: Clear on Logout (Quick Fix)**
```typescript
// In profile.tsx handleLogout
import { dbManager } from '@/lib/db/database';

const handleLogout = async () => {
  // Clear local SQLite data
  const db = await dbManager.initialize();
  await db.execAsync('DELETE FROM flashcards');
  await db.execAsync('DELETE FROM word_bank');

  // Then sign out
  await signOut();
};
```

**Option B: User-Scoped Data (Better Long-term)**
- Add `user_id` column to local tables
- Only show data for current user
- Sync with Supabase when online

**Option C: Move to Supabase Entirely**
- Migrate flashcards/word_bank to Supabase
- Full cloud sync
- Requires offline-first architecture

### Recommendation
Start with **Option A** for immediate fix, plan **Option B** for proper user data isolation.
