## CRITICAL

### C-1: API Keys Exposed Client-Side via EXPO_PUBLIC_ Prefix

**Files affected**:
- `lib/config/env.ts` — Gemini, OpenAI keys exposed via `EXPO_PUBLIC_` prefix
- `lib/voice/elevenLabsConfig.ts` — ElevenLabs API key via `EXPO_PUBLIC_ELEVENLABS_API_KEY`
- `lib/voice/googleTTS.ts:133` — Google TTS key via `EXPO_PUBLIC_GOOGLE_TTS_API_KEY`
- `lib/writing/writingAnalyzer.ts:19` — Gemini key read directly
- `lib/services/pathGeneration.ts:570,625` — Gemini key read directly

**Risk**: Any `EXPO_PUBLIC_*` environment variable is bundled into the JavaScript bundle, which is downloadable from the app binary. An attacker can extract these keys and:
- Use your Gemini API key (billed to you)
- Use your OpenAI Whisper key (billed to you)
- Use your ElevenLabs key (billed to you)
- Use your Google TTS key (billed to you)

**Impact**: Direct financial exposure. A single attacker can run up thousands of dollars in API costs.

**Recommendation**:
1. **Immediately**: Set API quota limits and billing alerts on all services (Gemini, OpenAI, ElevenLabs, Google Cloud)
2. **Before scale**: Move all API calls through a Supabase Edge Function proxy (like you already do for Claude/Anthropic in `lib/ai/claudeClient.ts` lines 235-258). The Edge Function holds the secret; the client only sends the auth token.
3. **Pattern to follow**: Your `claudeClient.ts` Edge Function approach is the correct architecture — replicate it for Gemini, ElevenLabs, OpenAI, and Google TTS.

## WARNING

### W-1: Test Screens Accessible in Production

**Files**:
- `app/test-elevenlabs.tsx` — Shows partial API keys in UI (line 461)
- `app/test-voice-system.tsx` — Displays API availability status
- `app/test-gemini-live.tsx`
- `app/test-writing-task.tsx`
- `app/test-cards.tsx`
- `app/test-interactive-scenario.tsx`

**Risk**: These routes are accessible in the production app bundle via Expo Router file-based routing. `test-elevenlabs.tsx` specifically renders partial API key values on screen (first 8 chars).

**Recommendation**: Either exclude these from the production build or add `__DEV__` guards at the top of each file to redirect away in production.

### W-2: User Conversation Content Logged to Console

**Files**:
- `lib/voice/hybridConversation.ts:255` — `console.log('[HybridConversation] User said:', userText)`
- `lib/voice/hybridConversation.ts:264` — `console.log('[HybridConversation] AI response:', aiText)`
- `lib/voice/geminiLive.ts:333` — `console.log('[GeminiLive] Input transcript (user):', ...)`

**Risk**: User speech content is logged in production. On iOS, these logs can be viewed via Console.app or crash log aggregators. This is a privacy concern, especially given your GDPR commitments.

**Recommendation**: Wrap all content-logging in `if (__DEV__)` guards or remove them entirely.

### W-3: Dependency Vulnerabilities (7 total, 6 high)

**Output from `npm audit`**:
- 6 **high** severity: All related to `node-tar` (path traversal, symlink poisoning, hardlink attacks)
  - Affects: `tar`, `cacache`, `@expo/cli`, `expo-edge-speech`
  - No fix currently available (upstream Expo dependency)
- 1 **moderate** severity: Also in tar dependency chain

**Risk**: These are build-time/install-time vulnerabilities in `node-tar`, not runtime client vulnerabilities. They affect `npm install` operations, not the running app.

**Recommendation**: These are low practical risk for a mobile app (tar is not used at runtime). Monitor for upstream fixes. Run `npm audit` again before each release.

### W-4: Supabase Anon Key in .env.example as Template

**File**: `.env.example` line 8

**Risk**: The `.env.example` correctly has placeholder values (not real keys). However, the actual `.env` file contains real production keys. While `.env` is properly in `.gitignore` and was never committed, there is no additional safeguard.

**Recommendation**: Consider using EAS Secrets or Expo's environment configuration for production builds instead of local `.env` files, reducing risk of accidental exposure.

### W-5: Some Gemini Calls Bypass Centralized ENV Config

**Files**:
- `lib/writing/writingAnalyzer.ts:19` — reads `process.env.EXPO_PUBLIC_GEMINI_API_KEY` directly
- `lib/services/pathGeneration.ts:570,625` — reads `process.env.EXPO_PUBLIC_GEMINI_API_KEY` directly
- `lib/gemini/staircase-generator.ts:9` — reads `process.env.EXPO_PUBLIC_GEMINI_API_KEY` directly
- `lib/gemini/lesson-composer.ts:12` — imports non-existent named export from env.ts

**Risk**: Inconsistent key access makes it harder to audit and rotate keys. The lesson-composer import (`EXPO_PUBLIC_GEMINI_API_KEY from '@/lib/config/env'`) references a named export that does not exist in env.ts — this may cause a runtime crash.

**Recommendation**: Standardize all key access through `ENV.GEMINI_API_KEY` from `lib/config/env.ts`.

## INFO

### I-1: .env File Security (PASS)

- `.env` is in `.gitignore` (line 43)
- `.env` was **never committed** to git history (verified via `git log`)
- `.env.example` contains only placeholder values
- `logEnvironmentStatus()` in env.ts correctly logs only presence/absence, not values

### I-2: Supabase Auth Storage (PASS)

- `lib/db/supabase.ts` uses `expo-secure-store` (Keychain/Keystore) for auth token storage
- Falls back to AsyncStorage only when SecureStore is unavailable (Expo Go, web)
- `autoRefreshToken: true` and `persistSession: true` are correctly configured
- `detectSessionInUrl: false` prevents OAuth URL-based session hijacking on mobile

### I-3: Prompt Injection Protection (PASS)

- `lib/ai/sanitize.ts` provides `sanitizePromptInput()` with:
  - Control character stripping
  - Unicode escape removal
  - Zero-width character removal
  - 46 injection pattern blocklist
  - Length truncation (500 char default)
- Used consistently in `lib/word-bank/initialVocabGenerator.ts` and `lib/ai/prompts/pathGeneration.ts`
- Not all user inputs go through this (route params are not sanitized), but route params are only used for IDs/slugs, not passed to AI prompts

### I-4: Privacy Infrastructure (PASS)

- `lib/privacy/consentManager.ts` — consent tracking for voice, privacy policy, ToS
- `lib/privacy/dataExport.ts` — GDPR Article 20 data portability
- `lib/privacy/dataDelete.ts` — GDPR Article 17 right to erasure
- `app/privacy-dashboard.tsx` — user-facing privacy controls
- Voice consent gate in `app/voice-conversation.tsx`
- Claude API key correctly proxied through Supabase Edge Function (server-side secret)
- ANTHROPIC_API_KEY is NOT `EXPO_PUBLIC_` prefixed — will not be bundled in production
